# 📚 Content Writing — શૈક્ષણિક લખાણ

**ગુજરાત સરકારી પરીક્ષાની તૈયારી કરતા વિદ્યાર્થીઓ માટે** Theory, MCQ, explanation લખવાના નિયમો.

> 🔗 Base નિયમો → **`chat-style`** · Data structure (`TestQuestion`, `TheoryData`) → **`web-app-development`**

---

## 🛑 સૌથી ઉપરનો નિયમ — હકીકત ખોટી ના હોય

**વિદ્યાર્થી આ વાંચીને પરીક્ષા આપશે. એક ખોટી હકીકત = એક ખોટો જવાબ.**

| બાબત | ફરજિયાત |
|:---|:---|
| તારીખ, વર્ષ, આંકડા | 🔍 **ચકાસવા** — યાદ પરથી નહીં |
| કાયદો, કલમ, બંધારણ | 🔍 સત્તાવાર source |
| વર્તમાન હોદ્દેદાર (મુખ્યમંત્રી, રાજ્યપાલ) | 🔍 **હંમેશા search** — બદલાતું રહે છે |
| ભૂગોળ, વસ્તી, ક્ષેત્રફળ | 🔍 તાજા આંકડા |
| યોજના, ઠરાવ | 🔍 વર્ષ સાથે ચકાસવું |

**ખાતરી ના હોય તો:** ❌ પ્રશ્ન બનાવવો જ નહીં. અંદાજથી લખવા કરતાં ઓછા પ્રશ્ન સારા.

⚠️ **બદલાતી માહિતી** (હોદ્દેદાર, આંકડા, યોજના) વાળા પ્રશ્નમાં **વર્ષ લખવું** — દા.ત. "2011 ની વસ્તી ગણતરી મુજબ..."

## 📝 MCQ પ્રશ્ન લખવાના નિયમો

### પ્રશ્ન (question)

| ✅ સારું | ❌ ખરાબ |
|:---|:---|
| એક જ વાત પૂછે | બે વાત ભેગી પૂછે |
| સ્પષ્ટ, 1–2 લીટી | અડધો ફકરો |
| પરીક્ષામાં આવે એવો | trivia કે બિનજરૂરી વિગત |
| નકારાત્મક હોય તો **bold** — "**કયું નથી**" | નકાર છુપાયેલો |

### Options (4 ફરજિયાત)

| નિયમ | વિગત |
|:---|:---|
| **બધા વિશ્વસનીય** | ખોટા options પણ સાચા લાગે એવા — "ચંદ્ર" જેવો દેખીતો ખોટો નહીં |
| **સરખી લંબાઈ** | સાચો જવાબ સૌથી લાંબો ના હોય (સામાન્ય ભૂલ) |
| **સરખું format** | બધા વર્ષ, કે બધા નામ — મિશ્રણ નહીં |
| **તાર્કિક ક્રમ** | આંકડા હોય તો ચઢતા ક્રમે |
| **`correctAnswer` વહેંચવો** | બધા જવાબ 0 કે 2 પર ના રાખવા — ફેરવવા |
| ટાળવું | "ઉપરના બધા" / "એક પણ નહીં" — શક્ય હોય તો નહીં |

### Explanation (ફરજિયાત)

**ફક્ત "સાચો જવાબ B છે" ના લખવું.** આ format:

```
[સાચો જવાબ કેમ સાચો — 1–2 લીટી]
[વધારાની ઉપયોગી માહિતી — 1 લીટી]
```

**ઉદાહરણ:**
> ✅ સારું: "સરદાર સરોવર બંધ નર્મદા નદી પર નવાગામ (નર્મદા જિલ્લો) ખાતે આવેલો છે. તેની ઊંચાઈ 138.68 મીટર છે અને તે ગુજરાત, મધ્યપ્રદેશ, મહારાષ્ટ્ર, રાજસ્થાન — ચાર રાજ્યોને પાણી આપે છે."
>
> ❌ ખરાબ: "જવાબ C સાચો છે."

## 📖 Theory લખવાના નિયમો

### રચના

| ભાગ | નિયમ |
|:---|:---|
| **Section** | એક section = એક ઉપ-વિષય |
| **લંબાઈ** | એક section max 5–6 લીટી — લાંબું હોય તો તોડવું |
| **Heading** | દરેક section નું સ્પષ્ટ title + યોગ્ય emoji icon |
| **કોષ્ટક** | યાદી, સરખામણી, આંકડા → **કોષ્ટકમાં** (વાંચવું સહેલું) |
| **Bold** | મુખ્ય શબ્દ, તારીખ, નામ **bold** — વિદ્યાર્થી ઝડપથી revise કરે |
| **ક્રમ** | સરળથી અઘરું, જૂનાથી નવું |

### 🎯 વિદ્યાર્થી-કેન્દ્રિત લેખન

- **પરીક્ષામાં શું પુછાય** તેના પર ભાર
- લાંબા ફકરા નહીં — **મુદ્દા** (bullet)
- અઘરો શબ્દ વાપરો તો કૌંસમાં સરળ અર્થ
- યાદ રાખવાની યુક્તિ (mnemonic) હોય તો ઉમેરવી
- દરેક chapter ના અંતે **📌 મુખ્ય મુદ્દા** — revision માટે

## 🗣️ ગુજરાતી ભાષાના નિયમો

| નિયમ | વિગત |
|:---|:---|
| જોડણી | **શુદ્ધ ગુજરાતી** — ખાસ કરીને ઈ/િ, ઉ/ુ, ં/ઁ |
| પારિભાષિક શબ્દ | ગુજરાતી + કૌંસમાં અંગ્રેજી — દા.ત. "લોકશાહી (Democracy)" |
| સંખ્યા | ગુજરાતી લખાણમાં અંગ્રેજી અંક (1, 2, 3) ચાલે — સુસંગત રાખવા |
| નામ | વ્યક્તિ/સ્થળના નામ સત્તાવાર જોડણી મુજબ |
| વાક્ય | ટૂંકા — 15–20 શબ્દથી લાંબા નહીં |
| સુસંગતતા | એક જ શબ્દ આખા chapter માં એક જ રીતે |

## 💾 Data Format નિયમો

- `TestQuestion` / `TheoryData` interface **બરાબર** પાળવો (structure → `web-app-development`)
- MCQ ઉમેરો → **`totalQuestions` update કરવો**
- `id` ક્રમમાં અને **unique**
- `correctAnswer` = index **0–3** (1–4 નહીં — સામાન્ય ભૂલ)
- `options` બરાબર **4** હોવા જ જોઈએ
- `explanation` ખાલી ના રાખવું
- Chapter/topic ના `id` **ક્યારેય ના બદલવા** — વિદ્યાર્થીનું saved progress તૂટે

## ✅ લખ્યા પછી Checklist

| # | ચકાસવું |
|:-:|:---|
| 1 | બધી હકીકતો ચકાસી? |
| 2 | દરેક પ્રશ્નમાં **બરાબર એક** સાચો જવાબ છે? |
| 3 | ચારેય options વિશ્વસનીય લાગે છે? |
| 4 | `correctAnswer` બધા options વચ્ચે વહેંચાયેલા છે? |
| 5 | દરેક explanation માં **કારણ** છે? |
| 6 | જોડણી અને ભાષા શુદ્ધ? |
| 7 | `totalQuestions` સાચો? |
| 8 | JSON/TypeScript structure valid — build પાસ થાય? |
| 9 | કોઈ પ્રશ્ન duplicate નથી? |

## ⛔ ક્યારેય નહીં
- ચકાસ્યા વગર હકીકત લખવી
- Explanation વગરનો MCQ
- એક પ્રશ્નમાં બે સાચા જવાબ
- દેખીતો ખોટો option ("ચંદ્ર પર", "કંઈ નહીં")
- બધા સાચા જવાબ એક જ position પર
- Chapter/topic ID બદલવો
- અંગ્રેજી-મિશ્રિત ભાંગેલી ગુજરાતી

## ✅ હંમેશા
- હકીકત ચકાસવી — ખાતરી ના હોય તો પ્રશ્ન ના બનાવવો
- કારણ સાથે explanation
- કોષ્ટક + bold થી revision સહેલું બનાવવું
- પરીક્ષાલક્ષી — trivia નહીં
- બદલાતી માહિતીમાં વર્ષ લખવું
